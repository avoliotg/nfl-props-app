## 2. THE CENTRAL FRAMEWORK: PRICE SYMMETRY AND LINE GRANULARITY

This is the project's one real structural finding and it has now **predicted
correctly five times in advance**.

**The claim.** A book can express its view through the LINE or through the
ODDS. Which one it uses is decided by how coarse the line grid is relative
to the outcome distribution.

| market | % symmetric | step as % of line | expresses view via |
|---|---|---|---|
| qb_passing | 99.6 | 0.2 | line |
| receiving | 95.3 | 1.4 | line |
| rushing | 91.4 | 1.4 | line |
| rush_attempts | 12.2 | 4.0 | **odds** |
| receptions | 5.3 | 15 | **odds** |
| NHL shots on goal | not yet bought | **33** | **odds, predicted** |

A symmetric two-sided price devigs to exactly 0.5000, meaning the book has
stated no player-specific probability: it has parked at the line and
charges the vig both ways.

**Consequences that follow from it:**

- Beta-against-the-line is the valid instrument on symmetric markets.
- The devigged-price encompassing test is a **receptions-only** method
  among the original four. `receptions_shipped_vs_price.py` correctly
  aborts on receiving, rushing and qb_passing because `book_p` barely
  varies.
- Rule 1's mechanism requires a book that places lines at the median, so
  it **cannot** transfer to a coarse market. Confirmed on rush_attempts
  below.

**Successful advance predictions:** receptions line-position null; rushing
and receiving line-position null; rush_attempts asymmetry and mechanism
failure; receptions open-to-close immobility (predicted 91.3% unchanged
from an independent dataset, measured 92.3%).

## 3. THE NULL-MAXIMUM SCHEDULE

The second most valuable thing produced. It measures what apparent edge
**chance alone** manufactures as cells narrow, via max-statistic
permutation over a pre-enumerated family.

| family | cells | null max ROI |
|---|---|---|
| broad conditional cells | 52 | +0.0542 |
| defensive streak templates | 22 | +0.1176 |
| player streak templates | 28 | +0.1411 |
| conditioned on bye weeks | 24 | +0.1549 |
| conditioned on defence quality | 40 | +0.1591 |
| **pure synthetic noise, no effect planted** | 52 | **+0.1661** |

**Rule 1's real edge is +0.0589, below every one of those bars.** So a
broad scan could never have found it; it required a narrow search with an a
priori threshold. And conditioning RAISES the bar faster than it raises any
signal.

This is the number to cite whenever a trend claim appears. A 12 to 16
percent ROI pattern is what noise produces in these families.

## 9. PROCESS STANDARDS, EARNED THE HARD WAY

### Verification

- **AST-based checks, never bare substrings.** Eight assertions once fired
  on correct edits because comments mentioned the token being counted.
- **Execute the changed path**, do not just compile it. `compile()` catches
  neither `NameError` nor bad printf specs.
- **Scan for names read but never assigned.** This caught `_PAGE` vs
  `PAGE` and, this session, a `DEFAULT_MARKETS` corruption.
- **Word-boundary regex for renames, never `str.replace`.** A blanket
  replace of `MARKETS)` turned `DEFAULT_MARKETS)` into `DEFAULT_markets)`.
- **Check for self-referential conditional defaults, ORDER-AWARE.** A
  rename produced `hours = hours if hours is not None else preset_hours`,
  an `UnboundLocalError` the unresolved-name scan cannot see. The check
  must be order-aware or it flags the standard
  `stats = stats.to_pandas() if hasattr(...) else stats` idiom.
- **The format-spec checker must require a conversion character and
  disallow a space after `%`.** The naive pattern flags prose like
  "95% coverage" because `% c` looks like a space-flagged `%c`. Correct
  pattern: `%(?! )[-+#0]*[0-9.]*[diouxXeEfFgGcrsa]`.
- **A format string split across two `print` calls** shipped a
  `TypeError` that fired only after the statistic printed. Per-string
  checks pass because each string is individually valid.
- **Normalise whitespace before substring probing.** Hard-wrapped help text
  breaks spaced matches.
- **Test fixtures from the patch's own anchor text**, not hand-counted
  indentation. Five fixtures failed that way.

### Statistics

- **Permutation nulls must be checked against planted data first.** A
  within-cell shuffle is DEGENERATE when the per-cell rates are under test:
  sd 0.0000, p 1.0000 against a true rho of -0.88.
- **Max-statistic permutation for any scan**, because it corrects for
  family size AND cell overlap. A Bonferroni cannot do the second.
- **Print the MDE beside every null.** A null without it is not a null.
- **Circularity check on anything derived from the graded outcomes.** The
  -0.7751 became -0.9000 lagged, which was fine, but the first version was
  partly definitional.
- **An ordering is not an edge.** rho -0.90 with four of five bins losing.
- **Reproduce a published figure before producing a new one.** This is a
  hard gate. It caught the `split_qb_rushing` omission.

### Workflow

- `git --no-pager` always; plain `git diff` opens `less`.
- Assert match counts before any patch; read files in binary to preserve
  CRLF.
- One season at a time on any purchase, so a defect costs 11,400 rather
  than 45,600.
- SQL goes in the Supabase SQL editor, not the terminal.
- `python script.py`, never `script.py`, or Windows swallows the arguments
  and exits silently.
- Postgres has no `round(double, int)`; cast `percentile_cont` to numeric.

## 12. THE HONEST SUMMARY

Across both sessions: **one validated rule holding up under scrutiny and
gaining a measured mechanism, one structural framework that has predicted
correctly five times, one quantified schedule of what noise manufactures,
and roughly a dozen pre-registered nulls.**

Ted pushed back, correctly, on my framing that broad trend-hunting is
inherently dangerous. The right position is that searching more is correct
when a null costs an afternoon and a false positive costs money, PROVIDED
the correction scales with the search. That reframing produced the
null-maximum schedule, which is more useful than most positive results
would have been.

The models do not work and that is now well established rather than
suspected. What works is finding where a book's pricing convention leaves
something on the table, and that needs no model at all.
